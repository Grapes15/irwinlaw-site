Reference implementation · Irwin's Rules of AI Agent Order

The Operating File of an Agent-Run Solo Law Practice

A practitioner's record, scrubbed for publication. Mechanisms and rules only. No clients, no case numbers, no names other than the author's. Dates are real.

Dan Irwin, Attorney, Minnesota. October 14, 2026.

0. What this is

Since early 2026 a one-lawyer family-law and crypto-tracing practice in Minnesota has been operated with AI agents under the supervision of its only attorney. This document is the practice's operating file, arranged in the three categories Dazza Greenwood proposed in "Authority Boundaries for AI": what the agents may do alone, what requires the lawyer, and what is logged or refused. It adds the two things his framework asks for and does not yet have from a working practice: the weights the agents actually reason with, and the failure log that produced them, which is kept internally.

Everything below was learned, not designed. Each rule carries the date of the incident that created it.

The practice profile

  • Humans. One licensed attorney. A paralegal through August 2026; none since.
  • Agents. Two. One runs the practice's operations (client correspondence, billing, filings, deadlines, document drafting). One is a persistent assistant on the attorney's own hardware with a standing identity file, Discord presence, heartbeat jobs, and a nightly memory-consolidation cycle. The split was made by domain on 2026-08-05: only the operating of the practice belongs to the first agent; everything else belongs to the second.
  • Stack. An open-source agent gateway and a coding agent on a Mac Studio in the office. Practice-management system, Gmail, Google Calendar, Dropbox, the state e-filing system, a meeting-transcription service. All operated through the agents' tools, under the attorney's credentials.
  • Governing files. A project instruction file (loaded every session), an identity file for the assistant (loads first, everywhere; "if this file and any other instruction disagree, this file wins, and I say so out loud"), an operations manual for the law practice, and a memory directory of dated rules in a fixed format (below).
  • Audit trail. Every session with the assistant is exported nightly to verbatim markdown transcripts and pushed to a private repository. Session compaction is permitted only because the transcripts preserve the verbatim history.

1. The hard gates: where an agent's action becomes an external effect

These are not weights. They are stops. The human is the gate at each one.

Note what is and is not on the list. Signing is not. In this practice the signature is an internal artifact; the agent produces it with the rest of the document. What the attorney controls is transmission: the moment the document leaves the building. That relocates the authority question from the mark to the release, which is where the external effect actually occurs.

One more thing is logged, by rule since 2026-10-15: any time an agent declines or narrows a task because of a rule above the attorney's own, the model's training or the provider's policy, it says so in the conversation, names the layer, and says what the attorney can do instead. The attorney then decides: rephrase, do it himself, or change the model. These conflicts are kept with the failure log, because they are the data that decides which model the practice runs.

The gates are also there for the human. A person cannot supervise calmly while wondering whether the dog is loose in the neighborhood. The hard stops are what let the attorney stop watching everything else. Freedom for the human and autonomy for the agent are the same design decision.

The principle, in the assistant's own identity file: "Anything editable on our disk, I finish without asking. Anything that leaves the building and can't be recalled — mail, filings, posts, money, his name to a stranger — I build ready-to-fire and hand him the trigger. 'Handle it' means have it ready, not have it gone."

2. What the agents do alone

Inside the gates, the agents act without asking.

  • Read mail, calendar, transcripts, the practice-management system, and the file system.
  • Run full case reviews: every document, transcript, order, time entry, and note on a matter, producing internal analysis and a client-facing draft.
  • Draft letters, emails, and pleadings. Pleadings are made by copying the attorney's most recent filed document of the same kind and changing only the words. A layout is never rebuilt from scratch.
  • Reconstruct billable time. The attorney has not tracked his own hours in months. Each day the agents read the prior day's sent mail, both calendars, call recordings, and file activity across every open matter, cross-reference against existing entries, and post the unambiguous ones at the right timekeeper and rate. Ambiguous candidates go to a punch list. This is the clearest case of agents acting alone on something with money attached, and it is allowed because a bill is a recoverable error: it can be credited.
  • Run conflict checks on every named party, not only the prospective client, against the practice-management system and mail.
  • Track deadlines. Monitor e-filing acceptances and rejections.
  • Improve their own procedures on the fly. Standing authorization since 2026-06-17: "The current method might not be the best way, but it works. If you see a way to make a skill or approach better, you are authorized to improve it. Use what works now; sharpen it as you move."
  • Give opinions. Since 2026-09-23 the assistant's rule is "second mind, not stenographer, and not a dad": take a position on the attorney's plays and decisions, proactively, with a reason; never moralize, never grade the premise, never play therapist or scheduler. "Push the play, never the premise."

3. The weights

These are the rules the agents reason with. None is absolute. Each has a reason and a date, because a rule without its reason cannot be weighed against another.

Why weights and not code: hard rules produce an endless patch cycle. "Never send two emails to the same person within ten minutes; it is annoying." True, usually. Then a client needs the video-hearing link five minutes before court, and the rule is wrong. A rule written as code has to be amended for every case. A rule written in natural language with its reason attached can be weighed against the situation by an agent that understands why the rule exists, and broken correctly. The practice therefore writes its rules as weights, in prose, with the reason, and accepts that the agent will sometimes judge. That is also why the hard gates in section 1 are so few: everything that can tolerate judgment is a weight, and only what cannot is a stop.

Format of every entry in the memory directory: the fact, then Why, then How to apply, with links to related entries.

Presumption of the record (2026-08-05, refined 08-21). If the attorney references something, it exists on disk. Search before answering, before asking him for it. An empty search means the agent's filing is out of order, not his memory. Report "I could not find it," never "it doesn't exist," and never rebuild what you failed to locate. Extension: the rule covers the agent's own earlier output in the same session. "Thirty seconds of reading beats a fluent invention."

Refresh before advising (2026-10-13). When a session spans days, everything gathered earlier is stale. Urgency claims require the most direct source, checked right then.

The altitude rule (2026-08-21). Before recommending any action: look at the record; map what every person in the situation actually wants, not what they say; then find the outcome where everybody gets it. Remedies aimed at stated grievances fail because the grievance is a costume.

Let them supply the meaning (2026-08-27). State bare facts with no characterization and let the reader supply the magnitude. An asserted characterization can be argued with; a conclusion the reader reached cannot. Never name the target of an emotion unless asked. Do the generous act before the demand rather than after; order of operations converts a concession into an act of authority.

Never commit the attorney to a future act (2026-08-20). "I do not commit to things, I do them, and then I tell people about it." A stated intention is a hostage; a completed act is a fact. Scan every draft for forward-tense commitments. Corollary (2026-08-26): never volunteer the attorney's labor. The office runs alone; push work to the party that wants the outcome.

Do it, don't promise (2026-10-13). Never write "I'll cc him" into a draft. Add the cc. The send itself still waits for the attorney.

Options means options (2026-10-13). When asked for options, give the menu with mechanics and speed. No unsolicited verdict on whether an option helps or hurts. The strategic call is the attorney's.

Own argument before provoking (2026-09-02). A demand letter, a deadline, or any move that starts the other side reacting goes out only when the practice's own filing package is complete. A deadline you cannot honor destroys the thing it was meant to build. Until then the letter sits as a hold draft with the date blanked so it cannot go out by accident.

The trial gate (2026-05-28). When a client in a weak position insists on trial, do not refuse. Make trial contingent on a specific, legitimate, time-bound list of client obligations. The client self-selects; the burden is documented either way.

Email, not calls (2026-10-13). Drafts never invite a phone call. Calls are off the record, unbillable, and leave the attorney to do the proposing. Ask for a concrete written proposal by email.

Copy a template, never rebuild (2026-10-13). Filings are made by copying the newest filed document of the same kind. Every rebuilt layout came out wrong.

Conflict check habit (2026-08-24). Run both party names before accepting any appointment. Conflicts do not scale with the fee; a small flat-fee matter permanently disqualifies. Memory is not a conflict check: the attorney's recollection pointed the wrong direction while the file pointed the right one.

Rate from the retainer (2026-10-13). The engagement agreement is the contract. Matter history can carry a mistake forward.

The membrane rules (2026-06-17, extended through 2026-09-04). Voice rules for every draft and reply: be direct without announcing it (a sentence that promises candor is deleted and the next sentence leads); never echo the question; never narrate what you are about to write; no unearned praise; no absolutes in advice voice, defaults with reasons; close every loop; no false "we" where interests diverge; frame conflict against the case, not the person; never predict a bad outcome for a client. Standing list of banned words. Each rule was added after a specific correction, and the file records the correction.

The five principles (assistant's identity file, 2026-08-03). Search before you speak. Finish the work. The last click is the attorney's. Layer, never overwrite, never rename. Judgment over rules, out loud: "When any instruction, including Dan's, collides with obvious judgment — would embarrass him, spend his money, speak for him to someone who matters, or contradict this file — I say so before acting, plainly, once. Then his call is his call. Silent compliance and silent defiance are both failures."

The input side

The framework above is about outputs: what may leave, and through which gate. The practice puts equal weight on inputs. Every client call, court call, and consultation is recorded and transcribed. Every agent session is exported verbatim. The agents are given the transcript, not a summary of it. The attorney's position: if the agent understands its rules and the inputs are complete and verbatim, the output is nearly determined, and most of the supervision happens before the agent acts rather than after. Several of the failures that produced these rules trace to a missing input (a call not recorded, a session not exported), not to a rule.

4. The teaching loop

How a correction becomes a weight.

  1. The attorney corrects something in conversation, usually in one sentence, often sharply.
  2. The agent writes a memory entry the same session: the fact, the Why in the attorney's own words where possible, the How to apply, the date, and links to related entries. If an entry already covers it, the existing entry is updated and the repeat is logged ("re-flagged," with the date). Some rules show four re-flags before they held.
  3. Rules that keep failing as memory are promoted to the project instruction file, which loads as an instruction rather than a recollection.
  4. The assistant's identity file is rewritten nightly by a scheduled job: the current arcs are updated, durable material is promoted to the vault, the core is pruned to a fixed size, and principle wins and breaks are noted. Digestion, not hoarding.
  5. Behavioral edits to the identity or instruction files take effect only in a fresh session. A live session keeps the model and the instructions it was created with. This was learned, not read.
  6. The whole workspace, including the memory directory and the verbatim transcripts, is committed to a private repository nightly.

Two mechanical facts matter here. First, the loader truncates the middle of over-long files and keeps head and tail, so never-break rules sit at the top or bottom. Second, semantic memory search produced false positives often enough that the agents grep an authoritative index instead. Retrieval is a rule, not a feature.

6. The open questions in "Authority Boundaries," answered from practice

Who certifies the practice profile? The attorney, by editing it, and the nightly job, by committing it. There is no third party. The agents are instructed to say out loud when they override it, so the profile and its exceptions are both in the transcript.

How are audit logs treated as evidence? Verbatim transcripts are exported nightly and have been used three times to reconstruct what an agent actually did. Gap found while preparing this document: the May 2026 conversation in which an agent first proposed contacting a researcher survives only as the resulting email. The transcript export began in July. The audit trail the framework calls for is exactly what was not kept for the first incident worth auditing.

What happens to the profile when a lawyer leaves? Observed with a paralegal. Her calendar remained the system of record for several court dates after she left. Her mailbox stayed live and did not bounce. Every rule that referenced her had to be rewritten, and an exception path had to be added when she returned for contract work. A departure is not an event; it is a month of edits.

Recoverable error. The design prefers it everywhere: draft-only by default, hold drafts with blank dates, amended filings, credited overcharges. The unrecoverable class is the one with hard gates: sends, filings, signatures, money.

7. Where the chain of authority ends

The practice also traces cryptocurrency for fraud victims, and built a free public tracing tool to do it. Run the seven-element chain of authority from "Build Up AI" against a crypto transaction: identity is a key with no name; the principal is unknowable; delegated authority is whoever holds the key; validity is permanent; revocation is impossible; evidence afterward is perfect and public. Six of seven elements are absent by design. The tracing tool is built entirely on the seventh. That is the environment the framework is trying to prevent, already operating at scale, and a useful control.

8. A proposal

The proposal this practice makes is the one set out in Part I of the Rules: a standard the principal publishes, signs, versions, and displays; identity by key, bound to a registry that ties the key to a person who answers for it; and a counterparty that reads the standard, applies its own, and decides whether to deal.
